### Exercise 02 — Справочники «Роли сотрудника», «Услуги», «Услуги мастера»

#### 1. CSV-структура `Роли сотрудника`

```markdown
entity,attribute_name,display_name,key_type,data_type,length,required,default_value,comments
StaffRoles,staff_role_id,Идентификатор записи роли сотрудника,PK,INTEGER,,yes,,Уникальный идентификатор записи
StaffRoles,employee_id,Сотрудник (FK к «Сотрудники»),FK,INTEGER,,yes,,Ссылка на сотрудника
StaffRoles,role_code,Роль сотрудника,,"VARCHAR",20,yes,,Значения: master, manager (может быть расширено)
StaffRoles,valid_from,Дата начала действия роли,,"DATE",,yes,current_date,С какого момента роль активна
StaffRoles,valid_to,Дата окончания действия роли,,"DATE",,no,,Позволяет хранить историю изменения ролей, пусто если действует по настоящее время
```

##### Пояснения по сущности `Роли сотрудника`

- **Назначение**: определяет, какую именно роль (мастер, менеджер и т.д.) выполняет сотрудник в системе:
  - в UC02, UC03 по роли определяется, какие сотрудники доступны для выбора мастера;
  - позволяет одному сотруднику иметь несколько ролей (например, «мастер» и «администратор»).
- **`staff_role_id` (PK)**: уникальный идентификатор записи о назначении роли.
- **`employee_id` (FK)**: связывает запись роли с конкретным сотрудником.
- **`role_code`**:
  - код роли, на который опирается бизнес-логика (фильтрация мастеров, разграничение прав и т.п.);
  - README_RUS прямо задаёт список значений: `master`, `manager`.
- **`valid_from`, `valid_to`**:
  - обеспечивают хранение истории ролей во времени;
  - удобно показывать проверяющему, что вы думаете о жизненном цикле не только сущностей, но и их ролей.

#### 2. CSV-структура `Услуги`

```markdown
entity,attribute_name,display_name,key_type,data_type,length,required,default_value,comments
Services,service_id,Идентификатор услуги,PK,INTEGER,,yes,,Уникальный идентификатор услуги
Services,service_name,Название услуги,,"VARCHAR",100,yes,,Отображаемое клиенту название услуги
Services,description,Описание услуги,,"VARCHAR",255,no,,Краткое текстовое описание услуги
Services,duration_minutes,Длительность услуги (минуты),,INTEGER,,yes,60,Используется при формировании слотов и расписания
Services,base_price,Базовая стоимость услуги,,"DECIMAL(10,2)",,yes,0.00,Используется для расчёта оплаты и скидок
Services,status,Статус услуги,,"VARCHAR",20,yes,active,Например: active, archived
```

##### Пояснения по сущности `Услуги`

- **Назначение**: справочник всех типов услуг, которые оказывает сеть:
  - используется в UC03 при выборе услуги клиентом;
  - используется менеджером при настройке расписания и прайса.
- **`service_id` (PK)**: уникальный идентификатор услуги.
- **`service_name`**: человекочитаемое название услуги (например, «Стрижка мужская»).
- **`description`**: опциональное поле для уточнения (например, что включено в услугу).
- **`duration_minutes`**:
  - важно для состыковки с понятием «слота» (1 час);
  - помогает объяснить проверяющему, как связаны длительность услуги и расписание мастера.
- **`base_price`**:
  - используется для расчёта стоимости визита и базой для скидок;
  - тип `DECIMAL(10,2)` — стандартный выбор для денежных значений.
- **`status`**:
  - позволяет «выключить» услугу из продажи, не удаляя исторические данные (например, при изменении ассортимента).

#### 3. CSV-структура `Услуги мастера`

```markdown
entity,attribute_name,display_name,key_type,data_type,length,required,default_value,comments
MasterServices,master_service_id,Идентификатор записи,PK,INTEGER,,yes,,Уникальный идентификатор записи
MasterServices,employee_id,Идентификатор сотрудника (мастер),FK,INTEGER,,yes,,Внешний ключ к сущности «Сотрудники»
MasterServices,service_id,Идентификатор услуги,FK,INTEGER,,yes,,Внешний ключ к сущности «Услуги»
MasterServices,status,Статус услуги мастера,,"VARCHAR",20,yes,active,Позволяет временно выключать услугу для мастера
```

##### Пояснения по сущности `Услуги мастера`

- **Назначение**: связывает конкретного мастера с конкретной услугой:
  - в UC03 по выбранной услуге и мастеру система должна проверять допустимость их сочетания;
  - служит для фильтрации: не каждый мастер выполняет все услуги.
- **`master_service_id` (PK)**: технический идентификатор записи связи.
- **`employee_id` (FK)**: указывает, какой мастер оказывает данную услугу.
- **`service_id` (FK)**: указывает, какую именно услугу выполняет мастер.
- **`status`**:
  - даёт возможность временно отключить услугу у мастера (например, мастер перестал выполнять окрашивание, но запись в истории сохраняется);
  - удобно при объяснении жизненного цикла связки «мастер–услуга».
